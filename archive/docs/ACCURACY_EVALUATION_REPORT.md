## 🎯 總結與建議

### 問題診斷

#### 1️⃣ **MIDI 檔案過度誤判** (138個假陽性)
**問題**:
- 極低閾值 (0.10) 導致高靈敏度
- 開頭 0.4 秒內集中出現誤判
- MIDI 轉 WAV 格式轉換可能引入瞬態雜訊

**建議**:
```dart
// 1. 加入「音檔開頭跳過」機制
if (time < 0.5) {  // 跳過前 0.5 秒
  continue;
}

// 2. 提高 Synthetic 音檔的最低閾值
_adaptiveThresholdMin = 0.15;  // 從 0.10 提升到 0.15

// 3. 加強靜音區檢測
if (frameEnergy < 0.30 && time < 1.0) {
  continue;  // 開頭低能量區域直接跳過
}
```

#### 2️⃣ **真實錄音雜訊過多** (93.1% 雜訊率)
**問題**:
- 大量諧波誤判 (C4/C5, E4/E5)
- 後處理過濾不夠嚴格
- Recall 太低 (28.6%),漏檢嚴重

**建議**:
```dart
// 1. 加強諧波過濾
bool _isLikelyHarmonic(int midiNote, List<DetectedNote> recentNotes) {
  // 檢查是否為最近檢測音符的諧波 (2x, 3x)
  for (final recent in recentNotes) {
    final diff = (midiNote - recent.midiNote).abs();
    if (diff == 12 || diff == 19) {  // 八度或十二度
      return true;
    }
  }
  return false;
}

// 2. 提高置信度門檻 (針對真實錄音)
if (_audioClassification?.type == AudioType.realRecording) {
  minConfidenceScore = 0.75;  // 從 0.62 提升到 0.75
}

// 3. 加強音符時長過濾
if (noteDuration < 0.20) {  // 從 0.10 提升到 0.20
  continue;  // 真實錄音的音符通常較長
}
```

#### 3️⃣ **通用改進建議**

**A. 閾值調整**:
```
Synthetic/MIDI: 0.15 - 0.35 (提高下限)
Real Recording: 0.50 - 0.85 (提高下限)
```

**B. 特殊時段處理**:
```dart
// 音檔開頭特殊處理
if (time < 0.5) {
  threshold *= 1.5;  // 開頭提高閾值 50%
}
```

**C. 諧波抑制**:
```dart
// 記錄最近 1 秒內的檢測音符
final recentWindow = <DetectedNote>[];

// 檢測時過濾諧波
if (_isLikelyHarmonic(midiNote, recentWindow)) {
  confidence *= 0.5;  // 諧波音符信心降低一半
}
```
